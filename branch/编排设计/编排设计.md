# 编排设计（本体核心）

本体唯一「自己拿主意」的步骤：定项目骨架与架构决策，不写专项实现。

## 步骤

1. **脚手架**：目录结构、命名约定、README/CHANGELOG/ LICENSE 基线、配置分层；
   可借 general-programming 的 `scaffold_project.py`，只传意图＋参数。
2. **架构决策**：模块边界、依赖方向、接口契约；每个岔路走双链辩论：
   `python ../../scripts/logic_chain.py debate --pro <论据> --con <论据>`。
3. **任务切分**：把实现切成可派发的子任务，逐条标注路由目标（见
   [子技能路由/](../子技能路由/子技能路由.md)）与验收标准。
4. **门禁定义**：打包/测试/远端三环节的通过条件，交占位子技能
   [打包发布/](../打包发布/打包发布.md) · [软件测试/](../软件测试/软件测试.md) ·
   [git远端管理/](../git远端管理/git远端管理.md) 细化。
5. **大纲审阅**：自审后记 `process_chain.py save --step 编排设计`。

## 输出

编排大纲（骨架＋决策＋子任务路由表＋门禁），写入逻辑链后进
[路由执行/](../路由执行/路由执行.md)。

## 红线

- 不得在本步写专项实现代码（实现属派发）；
- 未辩论的架构岔路不得直接落地。
